# ADR-0006 出站回复持久化与上下文重建

- 状态：Accepted
- 日期：2026-10-24
- 决策者：项目所有者
- 关联接口：`IF-MSG-001`、`IF-CTX-001`、`IF-SESS-001`、`IF-CTX-002`

## 背景

当前机器人成功回复只追加到进程内短期上下文，不写入 SQLite。进程重启后，模型只能看到入站消息，看不到自己之前的回复，导致对话不连续。

同时，当前 `PlatformConnector` 未接入发送路径，插件直接 `bot.send(event, reply.text)`，没有出站 message_id。

## 决策

M5A 采用以下方案：

- 机器人发送成功后，把回复写入现有 `messages` 表，设置 `is_self=1`。
- 增加 `origin` 区分 `inbound` / `outbound` / `system`。
- 增加 `turn_id`，把一轮用户消息和机器人回复归组。
- 发送接口不返回 message_id 时，生成 `local:<uuid>` 作为内部唯一 ID。
- 上下文从 SQLite 重建近期原文，不再只依赖内存。
- 触发判断继续跳过 `is_self=1`，防止自问自答。
- 发送失败不写入成功消息，避免伪造上下文。

## 后果

正面：

- 重启后上下文连续。
- 审计可以把入站消息、出站消息和 trace 关联起来。
- 后续摘要和记忆有稳定的消息来源。

负面：

- 需要区分“已发送”和“已生成但发送失败”。
- 需要处理发送接口没有 message_id 的情况。
- 需要迁移和上下文重建测试。
- 需要避免出站消息触发回复。

## 替代方案

- 继续只用内存：重启丢失，无法满足连续性。
- 另建 outbound 表：可行，但会分裂消息事实来源，增加 join 成本。

## 迁移与验收

- 备份当前 v1 数据库。
- 迁移 v2 增加必要字段/表。
- 测试：私聊两轮 -> 重启 -> 继续对话，模型能看到之前的问答。
- 测试：群聊 @ -> 回复 -> 重启 -> 再 @，上下文连续。
- 测试：出站消息入库但不触发回复。
- 现有测试继续通过，并新增迁移、outbound、turn 和重启恢复测试。
- M5A 于 2026-10-25 完成实现。
