# ADR-0005 审计默认只记录元数据

- 状态：Proposed
- 日期：2026-10-24
- 决策者：待确认
- 关联接口：`IF-AUD-001`、`IF-ERR-001`

## 背景

调用审计需要回答“这次回复用了什么上下文、花了多少 token、为什么失败”。但聊天正文、提示词和回复正文包含隐私，长期保存会扩大泄露面。

## 决策

- 默认只记录元数据、ID、token、耗时、状态和上下文清单。
- 默认不记录聊天正文、完整提示词、模型回复正文、Key、Token、Cookie。
- 通过消息 ID、摘要 ID、记忆 ID 组成“上下文清单”，需要时再回查本地数据库。
- 审计异步写入，有界队列，失败不影响回复。
- 错误请求 100% 记录；成功请求按采样率。
- 调试正文开关默认关闭，必须短保留期和本地访问限制。
- 审计只追加，不原地修改。

## 后果

正面：

- 降低隐私和密钥泄露风险。
- 审计表体积可控。
- 可以定位上下文组成和成本问题。

负面：

- 不能仅靠审计表还原完整对话。
- 排查某些问题需要关联本地消息库。
- 需要额外的 trace/span 和上下文清单设计。

## 替代方案

- 全量记录正文：排查方便，但隐私风险高。
- 不记录审计：成本低，但无法回答成本和上下文问题。

## 迁移与验收

- 新增审计表时默认不包含正文列。
- 增加脱敏测试，确认 Key、Token、正文不会进入审计。
- 模拟审计写入失败，确认回复仍成功。
- 设计 OTLP/JSONL 导出时保持同样的脱敏规则。
