# ADR-0002 SQLite 作为当前消息事实来源

- 状态：Accepted
- 日期：2026-10-24
- 决策者：项目维护者
- 关联接口：`IF-MSG-001`、`IF-DB-001`

## 背景

当前是本地单进程部署，消息量小，主要目标是可靠保存白名单群消息、去重和重启后查询。引入 PostgreSQL 或消息队列会增加部署和运维成本。

## 决策

- 第一版使用 SQLite。
- `messages` 和 `conversations` 是当前消息事实来源。
- 使用 WAL、`busy_timeout` 和 `BEGIN IMMEDIATE`。
- 迁移按版本执行，只增不改。
- 数据库文件不进入 Git。
- 未来多实例部署时再评估 PostgreSQL。

不把聊天历史只保存在内存，不把 SQLite 细节泄漏到应用层。

## 后果

正面：

- 零额外服务，备份和迁移简单。
- 支持事务、唯一键和本地查询。
- 适合当前单进程和低并发。

负面：

- 单写入者，不适合多实例并发写。
- 数据库文件损坏需要备份恢复。
- 大数据量下需要归档和索引维护。
- 当前 `last_seen_at` 可能因乱序事件回退，需要后续修正。

## 替代方案

- 只用内存：重启丢数据，不可接受。
- PostgreSQL：能力强，但当前部署成本过高。
- 文件日志 + 解析：查询和事务能力不足。

## 迁移与验收

- 迁移前备份数据库。
- 从 v1 升级到 v2 时保留已有消息。
- 增加迁移测试和重启恢复测试。
- 达到多实例、高写入或大数据量阈值时，启动 PostgreSQL 评估。
