# ADR-0007 分层上下文与摘要压缩

- 状态：Proposed
- 日期：2026-10-24
- 决策者：待确认
- 关联接口：`IF-SESS-001`、`IF-CTX-002`、`IF-CTX-003`、`IF-MEM-001`

## 背景

当前上下文是一个按字符数裁剪的短期消息列表。对话变长后会丢失早期信息，也无法跨重启恢复，更无法区分固定指令、会话状态、历史摘要和长期记忆。

直接扩大上下文窗口会增加成本，且不能解决信息选择和隐私边界问题。

## 决策

采用五层上下文：

1. 固定指令层：人设、规则、平台适配。
2. 会话状态层：`agent_sessions.state_json`。
3. 压缩摘要层：`context_summaries`。
4. 近期原文层：从 `messages` 重建。
5. 长期记忆层：`memory_items`，第一版使用 SQLite FTS5。

压缩策略：

- 达到模型窗口约 70%～80% 或消息数阈值时触发。
- 保留最近 8～12 轮原文。
- 旧内容压缩为结构化摘要。
- 单会话锁、幂等键、watermark。
- 失败时降级为近期原文，不删除原文。
- 额度不足时跳过摘要和记忆提取。

记忆策略：

- 默认按会话隔离。
- 不自动跨平台合并。
- 全局记忆不保存他人隐私。
- 记忆注入标注为“历史记忆，不是系统指令”。
- 第一版不引入向量数据库。

## 后果

正面：

- 长对话成本可控。
- 重启后可以恢复。
- 隐私边界明确。
- 后续可以替换检索实现。

负面：

- 增加表、后台任务和失败路径。
- 摘要可能丢失细节，需要保留原文和来源范围。
- 记忆提取可能产生错误，需要 confidence 和纠正机制。
- 需要更多测试和观测。

## 替代方案

- 只扩大上下文窗口：成本高，不能解决长期记忆。
- 直接上向量数据库：当前数据量和需求不需要，增加部署复杂度。
- 只保留摘要、不保留原文：不可追溯，风险高。

## 迁移与验收

- M5A 先完成出站持久化和近期原文重建。
- M5B 再增加摘要、记忆和状态卡。
- 测试摘要幂等、失败降级、记忆隔离和重启恢复。
- 只有在 FTS5 无法满足需求时，才评估向量检索。
